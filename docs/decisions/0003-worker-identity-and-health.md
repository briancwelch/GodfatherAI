# ADR 0003: Worker identities, outbound heartbeats, and discovery

- Status: Accepted within authorized Phase 03
- Date: 2026-10-15

Use a portable Python worker and shared Pydantic protocol v1 contracts. Workers only register and send health telemetry over outbound HTTP on loopback, or certificate-validated HTTPS for a future authorized private deployment. They never listen, execute work, install services, or grant host access. Redirects and environment proxies are disabled so bearer credentials cannot be forwarded to another origin.

Provision credentials through an offline command with existing database authority, rather than adding an unauthenticated bootstrap endpoint or sharing an enrollment password across nodes. Generate independent 256-bit bearer secrets; store only SHA-256 digests and revocation flags in PostgreSQL. The provisioning command's stdout is a one-time secret document; the local wrapper captures it directly into an exclusive ignored file. It must never enter shared logs. This is a local minimum authentication foundation, not browser sessions, remote invitations, or full Phase 09 RBAC.

An enabled administrator credential requires a platform administrator owner. Both founders have identical authority over shared enrollment and health controls. Worker credentials are bound to an existing enabled owner and a unique name within that owner. Their UUID reserves a persistent node identity before its first registration. Workers cannot choose IDs, impersonate owners, inspect other nodes, or call administrative APIs. Revocation is permanent for a credential; disabling a node is reversible. A fresh credential creates a fresh identity; token rotation preserving identity remains future hardening.

Each worker process creates a random session UUID. Registration and heartbeat serialize on the credential and node rows. A different session cannot take over while the previous session's heartbeat is within the offline threshold. Once expired, registration may replace that session; stale sessions then cannot send heartbeats. This is protection against duplicate telemetry processes, not the job attempt fencing required by Phase 04. A holder of the same node secret can still impersonate that node: protect and revoke leaked credentials.

Database dependencies use FastAPI function scope so transactions commit before a success response is sent. Commit failures return a safe error and roll back node/event changes. FastAPI's minimum version is 0.121 for this supported lifecycle; see its [dependency scope documentation](https://fastapi.tiangolo.com/advanced/advanced-dependencies/).

Keep connection health (`online`, `suspect`, `offline`) separate from the effective node state, which may remain `draining` or `disabled`. Initial thresholds are heartbeat 10 seconds, suspect at 20, offline at 30, with a 1-second sweep. Thresholds are validated and configurable. The API lifespan runs a small database sweep in a thread pool; PostgreSQL timestamps and events remain authoritative across restarts. Row locks coordinate multiple API processes. No Redis or separate monitoring service is needed. A late sweep after coordinator downtime can go directly to offline; there is no invented heartbeat history.

Registrations update normalized capabilities with primary/secondary specialties. Typed resource, runtime, installed-model, toolchain, isolation-mode and discovery-warning snapshots use the existing JSONB resource/runtime fields. Model inventory is an advertisement, not a configured model deployment or inference gateway. Administrative health controls cannot edit contribution policies, expose paths, authorize tools, or access hosts.

Use psutil for portable CPU/RAM telemetry (one runtime dependency) and its stubs for strict development typing. Read-only, bounded OS adapters report NVIDIA driver telemetry, macOS display/Metal reports, Windows CIM hardware inventory and Linux DRM/ROCm inventory. Driver/runtime reports do not prove successful inference. Missing probes return unknown fields or warnings. First CPU utilization is unknown until a subsequent sample. Apple unified memory is identified without inventing dedicated VRAM; the Windows 32-bit CIM AdapterRAM field is deliberately ignored. Simulators have an explicit `simulated` source and fictional hardware labels. No GPU or model runtime is a registration prerequisite.

Full user sessions, quotas, rate limits, credential rotation, remote invitation/distribution, production secret storage and public exposure remain later gates. All current services retain loopback publishing and internal-only databases. Tailscale will provide connectivity, never application authorization.
